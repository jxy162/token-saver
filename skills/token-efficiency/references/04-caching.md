# 04 缓存：前缀缓存与结果缓存

## 前缀缓存为什么有效

服务端把提示词前缀算出的 KV 状态缓存起来。下次请求如果**从头开始逐 token 完全一致**，这部分就不用重算，按更低的单价计费（常见 0.1x~0.5x）。一旦出现第一个不同 token，之后的内容全部失效——所以问题不是"内容像不像"，而是"从第几个 token 开始不一样"。

推论（直接决定工程写法）：

1. 稳定内容放最前，易变内容放最后。
2. 禁止在稳定区放：时间戳、随机 ID、`Date.now()`、动态排序的数组（`Object.keys` 顺序不稳定）、随环境变化的路径。
3. 前缀要达到平台最小长度（常见 1024 token，部分模型 2048），否则不生效。
4. 工具定义、schema 的字段顺序必须固定（序列化时排序）。

## 平台写法（以官方文档为准，参数名易变）

| 平台/服务 | 方式 | 关键点 |
| --- | --- | --- |
| OpenAI 及多数兼容端点 | 自动前缀缓存 | 无需代码，只要顺序对；命中量在 `usage.prompt_tokens_details.cached_tokens` |
| Anthropic | 显式 `cache_control: {"type":"ephemeral"}` | 最多 4 个断点；TTL 约 5 分钟，命中续期；写入约 1.25x、读取约 0.1x |
| Gemini | 显式 `cachedContent` | 需提前创建缓存对象，按存储时长单独计费 |
| DeepSeek / 部分国内兼容服务 | 自动前缀缓存 | 缓存命中价显著低于未命中价，同样要求前缀稳定 |
| 自建（vLLM/SGLang 等） | 开启 prefix caching | 显存换吞吐；对多路复用同一 system 的场景收益极大 |

先查平台文档确认三件事：**最小前缀长度、写入是否额外收费、TTL 多长**。这三项决定值不值得做。

## 值不值得：盈亏平衡

设前缀为 P token 的等价成本（1 单位 = 未缓存输入单价），共调用 n 次：

- 不用缓存：`n × P`
- 用缓存（写入 1.25x、读取 0.1x）：`1.25P + (n-1) × 0.1P`

令两者相等：`n = (1.25 - 0.1) / (1 - 0.1) ≈ 1.28`。**只要 TTL 内命中一次以上就回本**（Anthropic 档位）。若平台写入不额外收费（自动缓存类），第一次就赚。

反过来：低于最小前缀长度、或 TTL 内不会重复调用同一前缀，做缓存就是白工。

## 怎么把请求排成缓存友好

```bash
node scripts/prompt-cache-plan.mjs messages.json --out plan.json
```

它做三件事：把 `stability: "static"` 的块排到前面、算出可缓存前缀长度、给出 `cache_control` 断点建议，并在"标为 static 但疑似含时间戳/随机值"时报 warning。输入格式见 `assets/messages.example.json`。

典型结构：

```
[static] system 规则 + 输出 schema      ← 断点 1
[static] 长期文档 / few-shot            ← 断点 2（若 > 最小长度）
[volatile] 本轮检索结果
[volatile] 本轮用户输入
```

## 结果缓存（同一输入直接复用响应）

与前缀缓存互补：前者省"重算前缀"，后者省"整次调用"。

- **键要归一化**：去掉首尾空白、折叠空白、统一大小写（仅当语义无关时）、参数排序。键里必须包含**模型名、提示词版本号、温度等采样参数**——否则改了 prompt 还在吃旧答案。
- **TTL**：业务能接受多新的答案就设多短。分类/抽取类可以设天级，事实问答设小时级。
- **LRU 上限**：防止内存无限增长。
- **失效**：prompt 版本变更、知识库更新、模型升级时必须整体失效（版本号进键即可）。
- **只缓存可复用请求**：幂等、无副作用、无个性化（个性化会让命中率趋近 0）。

语义缓存（embedding 近似匹配）省得更多，但**必须有阈值校验 + 人工抽检**，否则会把"相似但不同"的问题答错。多见于客服 FAQ 场景，慎用于需要精确性的任务。

## 检查清单

- [ ] 前缀里还有时间戳/随机值/动态顺序吗？
- [ ] 前缀是否达到平台最小长度？
- [ ] 是否确认了写入成本与 TTL（写入 1.25x 需要至少一次命中才回本）？
- [ ] 结果缓存的键包含提示词版本号与采样参数吗？
- [ ] 缓存命中率有埋点吗（`cachedInputTokens / inputTokens`）？命中率骤降通常意味着有人改了前缀顺序。
