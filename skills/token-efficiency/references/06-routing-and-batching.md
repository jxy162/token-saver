# 06 路由与批处理：让便宜模型干便宜活

## 级联（cascade）：便宜先行，按需升级

```
请求 → 规则/小模型 → 校验器（schema、规则、置信度、自检）→ 通过则返回
                                              └─ 不通过 → 升级到更强模型（带上失败原因）
```

校验器是级联的关键。没有校验器就退化成"随机换模型"。可用的校验：

- 结构化输出是否符合 schema（最便宜，纯代码）
- 业务规则（枚举值、金额范围、ID 是否存在于输入）
- 模型自述置信度（可靠性一般，但可用于触发"再问一次强模型"）
- 交叉验证（两次便宜模型结果一致即采信）

**注意**：同一会话内频繁切换模型会让前缀缓存失效（缓存与模型绑定）。规则：**同一会话固定模型档位**，只在明确的"升级点"切换。

## 规则路由：用输入特征选档位

| 特征 | 判断 | 建议 |
| --- | --- | --- |
| 输入长度 | < 1k token 且无需全局理解 | 小模型 |
| 是否含代码/数学/多步规划 | 有 | 强模型 |
| 输出是否结构化且字段少 | 是 | 小模型 + schema |
| 是否高价值/高风险（法律、财务、对外发布） | 是 | 强模型 + 人工复核 |
| 是否重复出现在结果缓存里 | 是 | 直接复用，不调用 |

复杂度启发式（可作为打分起点，需按你的数据校准）：含代码块、公式、多问句、"逐步/step by step/分析"、多交付物、超长上下文 → 分数升高。

## 明确不该用大模型做的事

- 分类/打标（小模型或 embedding + 阈值足够）
- 格式转换（JSON↔CSV、字段重命名）：先看能不能用代码
- 去重、排序、计数、正则匹配
- 简单的意图识别（关键词/规则先兜一层）

这些任务用大模型的价格差常在 10~50 倍。

## 批处理与异步

- 平台提供的 batch 接口通常有显著折扣（常见 50%），代价是延迟到小时级。
- 适合：离线标注、历史数据回填、批量摘要、评测集跑分。
- 不适合：交互式请求。但**评测回归**一定要走批处理，否则每次改动都在用交互价试错。

## 单次多任务合并

把同一次调用的 3 个独立分类合并成一次结构化输出（数组 3 项），可省 2 次固定的 system+schema 开销。代价：失败面变大（一次失败三个都失败），且输出更长。适合高 QPS、短任务的场景。

## 蒸馏与微调（长期杠杆）

当某个任务的历史调用量足够大且稳定时，用它自己的输入输出对微调一个小模型，可把成本降一个数量级。前提：任务边界清晰、有质量评估手段、能接受一次性的数据准备成本。`08-governance.md` 的埋点（label + 输入输出样本）就是这件事的数据基础，别等到要做时才发现没留。
