# 02 提示词与输出：参数级节省

## 排序原则：稳定前缀在前，易变内容在后

一次请求的正确顺序（也是缓存友好的顺序）：

```
[1] 角色与规则（永不变）
[2] 输出 schema / 工具定义（很少变）
[3] 固定示例 few-shot（很少变）
[4] 长期参考文档（按版本更新）
[5] 本轮检索结果（每次都变）
[6] 本轮用户输入（每次都变）
```

把 [5][6] 插到前面 → 前缀缓存 100% 失效；把时间戳、随机 ID、`request_id`、动态排序的列表放进 [1]~[4] → 同样失效。这类值必须挪到尾部，或从提示词里删掉。

## 该删的 vs 必须留的

| 该删 | 必须留 |
| --- | --- |
| 客套与元话语（"请你作为…""希望你…""我认为你可以…"） | 角色边界与禁止项 |
| 重复的背景段落 | 输出 schema、字段名、枚举值 |
| 用自然语言描述结构（"请返回一个包含 file、line 的 JSON…"）→ 换成 schema  | 精确 ID、单位、时区、格式约定 |
| 冗长的 few-shot（3 个长例 → 1 个短例 + 1 个边界例）  | 反例（negative example），它通常最省"试错 token" |
| "请详细说明"这类无边界的输出要求 | 长度上限、字段上限 |

## 实测：一句话工单分类

同一个任务，只做"去客套 + 去重复背景 + 换 schema"，用 o200k_base 实测：

| 版本 | tokens |
| --- | --- |
| 冗长版（167 token） | 167 |
| 精简版（74 token） | 74 |

**-56% 输入**，且精简版同时约束了输出（`<=60字`、不复述、不解释），输出侧通常还能再降 20%~40%。

精简版长这样：

```
角色：客服助手。
背景：SaaS 工具，支持项目/成员/权限管理。
工单：导出 CSV 卡在 90%，刷新后需重新导出。
输出：{"category":"...","severity":"low|medium|high","suggestion":"<=60字"}；不要复述工单，不要解释推理过程。
```

注意它保留了全部**约束**（枚举、长度、禁止项），删掉的只有**修辞和重复**。

## 数据表示的 token 成本

同一个订单表，JSON 与 CSV：

| 形式 | tokens |
| --- | --- |
| JSON（重复键名） | 81 |
| CSV（表头一次） | 54 |

**-33%**。数据量越大差距越大。模型对 CSV/TSV 的解析能力通常够用，它只占一行 schema 说明。表格数据、日志、清单都适合 CSV；只有嵌套结构才必须 JSON。

## 参数级开关（按性价比排序）

| 参数 | 怎么设 | 效果 |
| --- | --- | --- |
| `max_tokens` | 取"合格答案 p95 长度 × 1.2"，不要留 4096 默认值 | 直接封顶输出成本，防止跑题长篇 |
| `response_format` / structured outputs | 强制 JSON schema | 去掉寒暄与解释，-10%~40% 输出 |
| `stop` | 明确的结束标记（如 `"\n###" `） | 提前结束生成 |
| 推理/思考预算 | 分类、抽取类任务关掉或给很小预算；只在数学/规划类开启 | 推理 token 常按输出计价且不可见 |
| `temperature` | 不影响 token 数，但高温导致格式不稳定 → 重试变多 | 间接影响 |
| 流式输出 | 用户满意即可提前断开 | 省尾部输出 |

**`max_tokens` 的两个坑**：设得太小 → 答案被截断，用户重问，总 token 更高；设成"和输入一样大" → 没有任何约束力。用你日志里输出长度的 p95 来定。

## 输出契约模板（直接抄）

```
输出要求：
1. 只输出 JSON，不要 Markdown 代码块、不要寒暄、不要解释推理过程。
2. schema: {"items":[{"id":string,"action":"retry|escalate|close","reason":"<=40字"}]}
3. 不要复述输入内容；引用时用 id，不要粘贴原文。
4. 字段为空时用 null，不要用自然语言占位。
```

## token 级压缩工具（LLMLingua 类）的边界

这类方法按 token 重要性做有损删除，通常省 20%~50%，但：

- **可以用于**：检索回来的长文档、长日志、被当"参考资料"塞进去的冗余文本。
- **不要用于**：输出 schema、工具定义、硬约束、需要引用精确的 ID/数值/代码。
- 压缩后必须跑一次质量回归（见 08-governance.md），并保留原文以便排查。

## 检查清单

- [ ] 稳定内容是否都在前缀，易变内容都在尾部？
- [ ] 提示词里有没有时间戳/随机值/动态顺序？
- [ ] 输出是否用 schema 约束，而不是自然语言描述？
- [ ] `max_tokens` 是否基于实测 p95 而不是默认值？
- [ ] 压缩提示词后，是否用同一批用例复核过质量？
