# 方法总览：token 消耗花在哪里，怎么减

按"作用点"分五层。**收益量级是常见区间，不是承诺**；任何一条都必须先用你自己的流量测量（见 01-measurement.md）。

| 层 | 方法 | 作用 | 常见收益量级 | 主要代价 |
| --- | --- | --- | --- | --- |
| 输入 | 上下文预算裁剪 | 按优先级把多段内容裁进预算 | 长任务输入 -30%~90% | 需要定优先级，可能丢信息 |
| 输入 | 历史压缩/摘要 | 把旧对话换成结构化摘要 | 多轮对话每轮 -50%~80% | 摘要可能丢约束，需保留 locked 内容 |
| 输入 | 检索片段收缩 | 先重排再截断，限条数与长度 | 注入 token -40%~80% | 召回不足会掉答案质量 |
| 输入 | 工具输出过滤 | 在工具层截断/过滤/聚合 | 工具密集循环 -60%~95% | 需要改工具调用方式 |
| 输入 | 精确引用替代全文 | 传行号区间/diff/symbol | -50%~90% | 需要工具支持定位 |
| 输入 | 去重与折叠重复行 | 折叠日志/重复段落 | -10%~60% | 少数场景重复是有意义的 |
| 输入 | 填充词与客套话清理 | 删冗余套话 | -1%~10% | 收益小但零风险 |
| 输入 | few-shot 精简 | 长示例换短示例 | prompt 的 -20%~50% | 可能影响准确率，要 A/B |
| 输入 | 数据表示改紧凑 | JSON 重复键改 CSV/列式 | 数据块 -30%~70% | 需要模型能稳定解析 |
| 输入 | 记忆分层 | 长期信息存外部，按需注入 | 视场景，可达一个数量级 | 工程量大 |
| 调用 | 输出上限 `max_tokens` | 封顶输出与跑题 | 输出 -20%~60% | 设太小会截断答案 |
| 调用 | 结构化输出 | 强制 JSON/字段，禁止寒暄 | 输出 -10%~40% | 需要 schema 维护 |
| 调用 | 停止序列/早停 | 命中标记即停 | 输出 -5%~30% | 标记选择要谨慎 |
| 调用 | 前缀缓存 | 复用不变前缀的 KV | 命中部分 -50%~90% | 顺序必须稳定；写入有成本 |
| 调用 | 结果缓存 | 同一输入复用响应 | 重复流量 -100% | 键设计/失效策略 |
| 调用 | 模型级联路由 | 便宜模型先跑，必要时升级 | 成本 -60%~95% | 需要校验器与兜底 |
| 调用 | 批处理接口 | 离线任务走 batch API | 常见 50% 折扣 | 延迟到小时级 |
| 调用 | 单次多任务 | 一次调用做多件事 | 省 N-1 次固定开销 | 任务耦合，失败面变大 |
| 调用 | 限制推理预算 | 显式控制 thinking/reasoning | 输出可 -30%~70% | 复杂任务可能掉质量 |
| 输出 | 禁止重述输入 | "不要复述代码/原文" | 输出 -10%~40% | 几乎无 |
| 输出 | 长度与格式约束 | "≤150 字/仅表格" | 输出 -20%~50% | 表达受限 |
| 工作流 | 搜索先行 | rg/grep 定位再读片段 | 单次探索 -70%~95% | 需要熟悉代码库工具 |
| 工作流 | 子代理隔离 | 搜索/阅读外包，只回结论 | 主上下文 -50%~90% | 需要编排与结果校验 |
| 工作流 | 状态外部化 | 计划/结论落文件 | 长任务显著 | 需要写文件的纪律 |
| 工作流 | 规则文件精简 | 只写非显然约束 | 每轮固定开销 -10%~50% | 写少容易漏关键约束 |
| 治理 | 用量埋点 | 按标签/模型归因 | 0（但让其余变可能） | 需要接入 |
| 治理 | 预算守门 | 单请求/会话/日预算 | 防跑飞 | 需要告警与熔断 |
| 治理 | 质量+成本双回归 | 优化后必须复核质量 | 防"省了但变差" | 需要用例集 |

## 怎么选（60 秒决策）

1. **先定位成本结构**：输入占比是多少？如果 input ≫ output，别去折腾输出格式，去看上下文与缓存。
2. **按"可逆性"排序**：先动调用参数（`max_tokens`、缓存、路由），这些不改语义；再动结构（预算、检索、压缩）；最后才动提示词文案。
3. **只保留两三个杠杆**：同时改五个地方就无法归因。一次改一个，用同一批用例对比。

## 常见组合（按场景）

| 场景 | 推荐组合 |
| --- | --- |
| 客服/工单分类 | 结果缓存 + 小模型固定档 + JSON schema + `max_tokens` 小上限 |
| 代码审查/长文档分析 | 前缀缓存（规则+schema 前置）+ 检索收缩 + 输出"只报问题" + 超长日志折叠 |
| 长会话助手 | 历史摘要 + 前缀缓存 + 最近 N 轮原文 + 状态外部化 |
| 智能体（多轮工具） | 搜索先行 + 工具输出截断 + 子代理隔离 + 每轮预算守门 |
| 离线批处理 | batch API + 小模型 + 结果缓存 + 去重输入 |

## 反例：看起来省其实更贵

- 用 token 级压缩工具压**指令**：省 20% 输入，却让 schema 失效，返工重试更贵。
- 为了缓存而把全部内容塞进 system：前缀是稳定了，但每次仍然全量付费（缓存只省"重复的部分"的单价，不是免费）。
- 无脑降低 `max_tokens`：答案被截断 → 用户重问 → 总 token 更高。
- 用旗舰模型做正则能做的工作：省下的解析代码时间抵不上 token 账单。
